questions:
  - question: "Quand utiliser const plutôt que let ?"
    reponse: "Par défaut, toujours const. Passer à let seulement quand la variable doit être réaffectée après sa déclaration, par exemple un compteur de boucle."
  - question: "Pourquoi préférer === à == ?"
    reponse: "== convertit les types avant de comparer, ce qui produit des résultats surprenants (0 == \"\" vaut true). === compare sans convertir, donc sans surprise."
  - question: "Comment parcourir un tableau sans gérer d'index manuellement ?"
    reponse: "Avec for (const element of tableau), qui donne directement chaque élément l'un après l'autre."
  - question: "Que renvoie une fonction sans instruction return ?"
    reponse: "undefined, systématiquement, même si la fonction affiche quelque chose avec console.log à l'intérieur."
  - question: "Quelle est la différence entre map et filter sur un tableau ?"
    reponse: "map transforme chaque élément et garde la même longueur. filter garde seulement les éléments qui passent un test, donc un tableau potentiellement plus court. Aucun des deux ne modifie le tableau d'origine."
  - question: "Comment extraire plusieurs propriétés d'un objet en une seule instruction ?"
    reponse: "Avec la déstructuration : const { nom, age } = objet crée directement deux variables nom et age."
  - question: "Comment sélectionner un élément de la page et changer son texte ?"
    reponse: "document.querySelector(sélecteur) renvoie l'élément, puis element.textContent = \"...\" change son texte affiché."
  - question: "À quoi sert event.preventDefault() dans un gestionnaire de soumission de formulaire ?"
    reponse: "À empêcher le rechargement de page que déclenche normalement la soumission d'un formulaire, pour laisser le JavaScript gérer la suite."
  - question: "Que se passe-t-il quand une erreur est levée dans un bloc try qui a un catch ?"
    reponse: "Le reste du bloc try est ignoré et l'exécution saute directement au bloc catch, qui reçoit l'objet d'erreur en paramètre."
  - question: "Que fait super(...) dans le constructeur d'une classe qui utilise extends ?"
    reponse: "Il appelle le constructeur de la classe parente pour initialiser la partie héritée de l'objet, avant tout accès à this."
